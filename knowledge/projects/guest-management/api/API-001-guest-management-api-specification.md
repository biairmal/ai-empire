## Overview

| Environment | Base URL |
|-------------|----------|
| Local | `http://127.0.0.1:8080/api/v1` |
| Staging | Not defined |
| Production | Not defined |

The API is used by the Guest Management web app (staff), by event staff doing check-in, and by guests through one public RSVP endpoint. The operational endpoints `/health`, `/ready`, `/metrics`, and `/swagger/*` are outside `/api/v1`. The Swagger UI requires HTTP Basic Auth (`SWAGGER_USERNAME` / `SWAGGER_PASSWORD`).

## Conventions

| Topic | Convention |
|-------|------------|
| Format | JSON (`application/json`), UTF-8 |
| Naming | snake_case field names |
| Dates and times | RFC 3339 (`start_date`, `end_date`, `created_at`, …) |
| Identifiers | UUID; an invalid UUID in the path returns 400 |
| Envelope | Every response except 204 is wrapped: `{"code":"OK","message":"success","timestamp":"…","data":…}` |
| Pagination | Page-based: `page` (starts at 1, default 1), `size` (default 20, max 100). Response `data` = `{items, total, page, size, total_pages, has_prev, has_next}` |
| Sorting | `sort=field,ASC\|DESC`, repeatable; only allow-listed fields, otherwise 400 |
| Filtering | `field=value` exact match; `field=value;like` partial match where supported (percent-encode `;` as `%3B` in hand-built URLs). Unknown filter keys are ignored; unknown operators return 400 |
| Nested resources | A child is always resolved within the parent in the URL. A child of another parent returns 404. Parent ids never appear in request bodies |
| Partial update | `PUT /{id}` is a partial update; omitted fields are unchanged |
| Deletes | Soft delete, 204 with an empty body |
| Idempotency | No idempotency keys. `PUT` sync and replace endpoints are safe to retry. RSVP confirm is idempotent for ticket issuance |
| Rate limits | Per client IP; default 10 requests/s with a burst of 20. Exceeding it returns 429 `TOO_MANY_REQUESTS` |

## Authentication and Authorization

- **Authentication:** `Authorization: Bearer <access_token>`, obtained from `POST /auth/login`. Access tokens last 15 minutes (`expires_in` is in seconds) and refresh tokens 7 days. HS256 signing. Claims: `sub` (user id), `type`, `tenant_id`, `role_id`. A refresh token sent to a protected route returns 401. Every route is protected unless it is listed as public: `/health`, `/ready`, `/metrics`, `/swagger/**`, `POST /auth/login`, `POST /auth/refresh`, `POST /guests/rsvp/*`.
- **Authorization:** Permission middleware per route group. On routes with `{event_id}`, the caller's event assignment role is checked if the system role doesn't grant the permission (ADR-004). A missing permission returns 403, and a missing or invalid token returns 401. A resource in another tenant returns 404.

| Resource group | Required permission | Tenant source |
|----------------|--------------------|---------------|
| `auth/*`, `guests/rsvp/{token}` | None (public) | — |
| `users/me/password` | Any valid access token | Token |
| `users`, `users/{id}`, `users/{id}/password`, `users/{id}/transfer-master` | `manage_users` (transfer also requires the caller to be the current tenant master) | Token |
| `events/{event_id}/staff` | `manage_staff` | Token |
| `events/{event_id}/ticket-types`, `event-categories/{category_id}/ticket-type-templates` | `manage_events` | Parent event or category |
| `events/{event_id}/guests` | `manage_guests` | Parent event |
| `events/{event_id}/scans` | `check_in` | Parent event |
| `tenants`, `event-categories`, `events`, `events/{event_id}/workflow-steps`, `event-categories/{category_id}/workflow-step-templates`, `message-templates` | **Login only, no permission (known gap, PRD-001 Q4)** | `events` takes `tenant_id` from the request body |

Seeded role grants: Super Admin has every permission. Tenant Admin has `manage_users`, `manage_events`, `manage_staff`, `manage_guests`, `manage_workflows`, and `check_in`. Tenant Staff has `manage_guests` and `check_in`. Usher and Photobooth Staff (event scope) have `check_in`. No endpoint lists roles (`roles` has no HTTP API).

## Endpoints

### Auth — `/auth`

| Method | Path | Body | Success | Errors |
|--------|------|------|---------|--------|
| POST | `/auth/login` | `{email*, password*}` | 200 `TokenPair` | 400, 401 `invalid email or password` (same message for an unknown email) |
| POST | `/auth/refresh` | `{refresh_token*}` | 200 `TokenPair` (new pair; the role is re-read from the database) | 400, 401 (invalid or expired token, wrong token type, deleted user) |

```json
{ "access_token": "eyJ…", "refresh_token": "eyJ…", "token_type": "Bearer", "expires_in": 900, "must_change_password": true }
```

### Tenants — `/tenants`

`GET /` (sort: `id, name, type, created_at, updated_at`; filters: `name`, `type`) · `GET /{id}` · `POST /` `{name*, type?, settings?, branding?}` → 201 · `PUT /{id}` (partial; omitted settings and branding are kept) · `DELETE /{id}` → 204. Errors: 400, 404, 409, 422.

### Users — `/users`

| Method | Path | Body | Success | Errors |
|--------|------|------|---------|--------|
| GET | `/users` | — (sort: `id, email, role_id, is_tenant_master, created_at, updated_at`; filters: `email`, `role_id`, `is_tenant_master`; always limited to the caller's tenant) | 200 page of `User` | 400, 401, 403 |
| GET | `/users/{id}` | — | 200 `User` | 400, 401, 403, 404 |
| POST | `/users` | `{email* (email), password* (min 8), role_id* (system role), is_tenant_master?}` | 201 `User` (`must_change_password: true`) | 400 (including an event-scoped role), 401, 403, 404 (role), 409, 422 |
| PUT | `/users/{id}` | `{email?, role_id?, is_tenant_master?}` (no password) | 200 `User` | 400, 401, 403, 404, 409 |
| DELETE | `/users/{id}` | — | 204 | 400, 401, 403, 404 |
| POST | `/users/{id}/password` | `{password* (min 8)}` | 200 `User` (`must_change_password` set to true) | 400, 401, 403, 404 |
| POST | `/users/me/password` | `{password* (min 8)}` | 200 `User` (`must_change_password` set to false) | 400, 401 |
| POST | `/users/{id}/transfer-master` | none | 200 target `User` | 400, 401, 403 (not the current master), 404 (target in another tenant) |

### Event categories and workflow-step templates

- `/event-categories`: `GET /` (sort: `id, source, tenant_id, name, created_at, updated_at`; filters: `name`, `source`, `tenant_id`) · `GET /{id}` · `POST /` `{source* app|tenant, tenant_id?, name*}` (app requires no tenant, tenant requires a tenant, otherwise 400) · `PUT /{id}` · `DELETE /{id}`.
- `/event-categories/{category_id}/workflow-step-templates`: `GET /` (sort: `id, name, order_index, allows_multiple, created_at, updated_at`; filter: `name`) · `GET /{id}` · `POST /` `{name*, order_index* ≥0, allows_multiple?, ticket_type_applicability?}` · `PUT /{id}` · `DELETE /{id}`. A duplicate `order_index` returns 409.
- `/event-categories/{category_id}/ticket-type-templates` (`manage_events`): `GET /` (sort: `id, name, created_at, updated_at`; filter: `name`) · `GET /{id}` · `POST /` `{name*, rules?}` · `PUT /{id}` · `DELETE /{id}`. A duplicate name returns 409, and an unknown category returns 422.

| POST / GET / PUT / DELETE | `/events/{event_id}/workflow-steps[/{id}]` | `{name*, order_index*, allows_multiple?}` | 201 / 200 / 200 / 204 | 400, 404, 409 |

| Method | Path | Body | Success | Errors |
|--------|------|------|---------|--------|

| POST | `/` | `{name*, rules?}` | 201 `TicketType`; entitled to all current steps | 400, 401, 403, 409, 422 |

### Guests — `/events/{event_id}/guests` (`manage_guests`)

| Method | Path | Body | Success | Errors |
|--------|------|------|---------|--------|
| GET | `/` | — (sort: `id, name, rsvp_status, created_at, updated_at`; filters: `name` (exact or `;like`), `email` and `phone` (exact only; `;like` returns 400), `rsvp_status`) | 200 page of `Guest` | 400, 401, 403 |
| POST | `/` | `{name*, email* (email), phone?, ticket_type_id?}` | 201 `Guest` (`rsvp_status: none`) | 400 (ticket type from another event), 401, 403, 422 |
| GET | `/{id}` | — | 200 `Guest` including `ticket` once issued | 400, 401, 403, 404 |
| PUT | `/{id}` | `{name? (min 1), email?, phone?, ticket_type_id?}` | 200 | 400, 401, 403, 404 |
| DELETE | `/{id}` | — | 204 | 400, 401, 403, 404 |
| POST | `/{id}/invitation` | none | 200 `{guest, invitation_token}`; status becomes `invited`, a message is published, and a ticket is issued now if the event has `rsvp_required = false` | 400 (no ticket type), 401, 403, 404 |

### Guest RSVP — public

| Method | Path | Body | Success | Errors |
|--------|------|------|---------|--------|
| POST | `/guests/rsvp/{token}` | `{"status": "confirmed" \| "declined"}` | 200 `Guest`. Confirm issues a ticket if none exists and the event has `rsvp_required = true`. Decline never voids an existing ticket | 400, 404 (unknown token) |

### Scans — `/events/{event_id}/scans` (`check_in`)

| Method | Path | Body | Success | Errors |
|--------|------|------|---------|--------|
| POST | `/` | `{qr_code*, workflow_step_id*}` | 201 `ScanLog` | 404 (QR code not found on this event, or unknown step), 409 (ticket invalidated), 400 (step from another event), 400 (ticket type not entitled), 409 (step already completed), 401, 403 |
| GET | `/` | — (sort: `id, scanned_at`; filters: `ticket_id`, `workflow_step_id`) | 200 page of `ScanLog` (read `total` for counts) | 400, 401, 403 |

The checks run in the order listed in the POST row, and the first failure is returned. On success, an `active` ticket becomes `used`.

### Staff — `/events/{event_id}/staff` (`manage_staff`)

`GET /` (sort: `id, user_id, role_id, created_at, updated_at`; filters: `user_id`, `role_id`) · `GET /{id}` · `POST /` `{user_id*, role_id*}` → 201. Checks, in order: the event is in the caller's tenant (404), the user is in the same tenant (404), the role exists (404) and is event-scoped (400), and the user has no active assignment on the event (409). · `PUT /{id}` `{role_id?}` · `DELETE /{id}` → 204 (a user can be re-assigned later).

### Message templates — `/message-templates`

`GET /` (sort: `id, source, tenant_id, event_id, name, channel, created_at, updated_at`; filters: `name`, `source`, `tenant_id`, `event_id`, `channel`) · `GET /{id}` · `POST /` `{source* app|tenant|event, tenant_id?, event_id?, name*, channel* email|whatsapp, subject?, body*, variables?}` · `PUT /{id}` · `DELETE /{id}`. Scope rules: app has neither tenant nor event, tenant has a tenant only, and event has both. Email requires a subject, and WhatsApp must have none. A violation returns 400. A duplicate (name, channel) within a scope returns 409.

### Operational

`GET /health` → 200 always · `GET /ready` → 200, or 503 when the database or Redis ping fails or shutdown is in progress · `GET /metrics` (Prometheus, when enabled) · `GET /swagger/index.html` (Basic Auth).

## Errors

Errors use go-sdk's envelope, **not** RFC 9457 Problem Details:

```json
{
  "code": "ERROR",
  "message": "user not found",
  "timestamp": "2026-09-17T12:00:00Z",
  "error": { "code": "NOT_FOUND", "message": "user not found", "meta": {} }
}
```

Validation failures put per-field details in `error.meta`. Field names match the JSON names.

| Code / type | HTTP status | When it happens | Client action |
|-------------|-------------|-----------------|---------------|
| BAD_REQUEST | 400 | Invalid body, UUID, query, sort field, or filter operator; violated business rule (scope, cross-event reference, role scope, no ticket type, `;like` on email or phone) | Fix the request; show the field errors |
| UNAUTHORIZED | 401 | Missing, invalid, or expired token; refresh token on a protected route; bad credentials | Refresh once, then send the user to login |
| FORBIDDEN | 403 | Permission missing; transfer by a non-master | Hide the action |
| NOT_FOUND | 404 | Unknown id, or an id belonging to another tenant, event, or category; unknown RSVP token or QR code | Show "not found" |
| CONFLICT | 409 | Duplicate unique value; duplicate staff assignment; step already completed; ticket invalidated | Show the message; don't retry unchanged |
| UNPROCESSABLE_ENTITY | 422 | Database rejected the entity (for example a foreign key to a missing category) | Fix the referenced ids |
| TOO_MANY_REQUESTS | 429 | Rate limit exceeded | Back off and retry |
| INTERNAL | 500 | Unexpected error (logged with request id) | Retry later; report the `request_id` |
| SERVICE_UNAVAILABLE | 503 | `/ready` only | Stop routing traffic to the instance |
